# Apt 0x801440C4-0x8014A18C: render state, callback table, paths, Date, events

Slice of the 2D UI library at 0x8012AD10-0x80151F80. The whole library is **EA's "Apt"**
(an ActionScript/Flash-derived runtime; The Sims 2 keeps the names: `setVertexMatrix`,
`setColourTransform`, `getStageWidth`, `AptAuxPCEorGL_*`, `SimsAptMalloc`). It is plain C
compiled at **-O0** (frame pointer r31, locals on the stack), not the C++ of the game code.
Source: `src/ui/Unk801440C4.c`, built with `tools/tu_ui.sh`.

Nothing in this slice draws. It holds (a) the **render state** that every display object's
draw call pushes/pops (colour transform + 2D matrix), (b) the **platform callback table**
through which Apt reaches the game, (c) path building (`_level0/instance3/...`), (d) the
ActionScript `Date` class, (e) clip-event name -> flag mapping, (f) the action bytecode
fix-up pass. Screen-space coordinates only appear as the matrix and the stage size.

## 1. Render state (the thing to hook for widescreen)

`RState`, initialised by `fn_8014739C(RState*)` (one instance, created by `fn_80132B2C`):

| offset | size | meaning |
|---|---|---|
| 0x000 | 0x20 | colour transform: `mul[4]` r,g,b,a at 0x00, `add[4]` r,g,b,a at 0x10 (identity: 1,1,1,1 / 0,0,0,0) |
| 0x020 | 0x18 | current matrix, 6 floats `m00 m01 m10 m11 tx ty` at 0x20,24,28,2C,30,34 |
| 0x038 | 16*0x20 | colour transform stack |
| 0x238 | 16*0x18 | matrix stack |
| 0x3B8 | 4 | colour transform stack depth |
| 0x3BC | 4 | matrix stack depth |

Matrix convention: `x' = m00*x + m01*y + tx`, `y' = m10*x + m11*y + ty`. Note the field order
is `m00, m01, m10, m11` (so in Flash terms 0x24 is `c`, not `b`). Matrices are in **Flash
pixel units (SWF twips already divided by 20)**; there is no 640x480 constant in this slice.

Functions (all take the RState first):

| address | role |
|---|---|
| 0x8014739C | init: identity cx, identity matrix, both depths 0 |
| 0x8014747C | push colour transform (copies 0x00..0x1F to `stack[depth++]`) |
| 0x80147520 | pop colour transform (copies `stack[--depth]` back, no callback) |
| 0x801475C0 | concat colour transform: `mul *= o.mul; add += o.add`; then calls callback slot 0x70 |
| 0x80147764 | push matrix (`mstack[mdepth++] = m`) |
| 0x801477DC | pop matrix (`m = mstack[--mdepth]`), then callback slot 0x6C with `&m` |
| 0x80147884 | `out = b * a` (a copied first, so out may alias a): 2x2 product plus translation; `(a, b, out)` |
| 0x80147A00 | concat: `m = o * m` via 0x80147884, then callback slot 0x6C |
| 0x80147A70 | grow a rect `acc` by the bounds of rect `r` (xmin,ymin,xmax,ymax) transformed by the current matrix |
| 0x801476B4 | get current matrix; if `mdepth > 0` copy `m`, else copy the identity at `lbl_8033D270` |

Callers: `fn_8013D198` (draw one object) does push cx (0x8014747C), push matrix (0x80147764),
concat cx (0x801475C0), concat matrix (0x80147A00), draws, then pops (0x80147520 / 0x801477DC).
`fn_8014041C` (containers, 0x80140658/0x801406C0 area) uses the same set plus 0x801476B4;
`fn_80140BBC`/`fn_8013FBB4`/`fn_8013FAF4` use push/concat/pop and 0x80147A70 (bounds).

**Where the matrix finally becomes pixels**: every matrix concat / pop calls callback slot 0x6C
(`set vertex matrix`). In the game that is `fn_80104644` (0x80104644): it copies
`m00,m01 -> 0x802F788C+0x00,0x04`, `m10,m11 -> +0x10,+0x14`, `tx,ty -> +0x30,+0x34` of
`lbl_802F788C` (0x40 bytes, a 4x4-style float array, rows of 16 bytes; the rest is the
constant remainder). Colour transform changes call slot 0x70 = `fn_801045EC`, which copies
mul to `lbl_802F83F8` (0x10) and add to `lbl_802F8408` (0x10). Scaling x of the matrix at
this point (or of `lbl_802F788C` when drawing) is the narrowest place for a widescreen fix
for everything Apt draws through the matrix path.

## 2. Platform callback table `lbl_8033D1E0` (0x7C bytes, .bss, filled at run time)

Filled by `fn_80104E14` (0x80104E14; "AptInit(width, height)", called from 0x8010602C with the
app object `lbl_8037C198` fields +0x14 width and +0x18 height as ints; it converts them to floats and passes
them to `fn_80104790`, a `blr` stub = Sims 2 `hardwareInit(float,float)`). Slots (index = offset/4):

| slot offset | game function | notes |
|---|---|---|
| 0x00 | 0x801038AC | alloc (blocks <= 8 bytes from a free list, else `fn_80169F1C`) = `SimsAptMalloc` |
| 0x04 | 0x80103908 | free = `SimsAptFree` |
| 0x08 | 0 (null) | wrappers 0x80144DD8/0x80144E30 call it with two args: never reached |
| 0x0C | 0x80104698 | `blr` |
| 0x10 | 0x80104694 | `blr` |
| 0x14 | 0x80103E20 | varargs trace function (spills r4-r10 and f1-f8) = `debugPrintStub` |
| 0x18 | 0x80103E70 | `blr` |
| 0x1C | 0x80103E6C | `blr` |
| 0x20 | 0x80104C34 | |
| 0x24 | 0x80104D7C | calls 0x80104A6C |
| 0x28 | 0x80104D78 | `blr` |
| 0x2C | 0x8010396C | `blr` (4 bytes) = `command` |
| 0x30 | 0x80103ADC | string handler (strlen, callback) |
| 0x34 | 0x80103970 | string handler (strcpy/strcat/strcmp) = `setExternVariable` |
| 0x38 | 0x80103B34 | string handler (strcmp, callback) |

| 0x40 | 0x80104774 | |
| 0x44 | 0x80104768 | |
| 0x48 | 0x80104680 | returns 0 |
| 0x4C-0x54 | 0x80104690, 0x8010468C, 0x80104688 | `blr` stubs |

The order follows the declaration order of The Sims 2's callbacks (`Malloc`, `Free`,
`command`, `setExternVariable`, ..., `loadTexture`, `setColourTransform`,
`setVertexMatrix`, ...) only roughly; the two matrix/cxform slots are certain (their bodies copy a
matrix / two vec4), the rest are positional guesses. `lbl_8033D270` (0x18 bytes) is the identity
matrix returned by 0x801476B4 when the matrix stack is empty (set up at run time).

## 3. Display-object (movie clip) node fields seen here

The path builders (0x8014973C slash form, 0x801498B0 dot form, wrappers 0x80149A14 and
0x80149A90) read these fields of a display node:

| offset | meaning |
|---|---|
| 0x04 | `_level` number (root nodes) or the running instance counter used for auto names |
| 0x08 | instance-name value (an Apt string value) or 0 |
| 0x48 | parent node pointer (0 for a level root) |

`GetTargetPath(node, buf)` gives `"_level0"`, `"_level0/name"`, `"_level0/instance3"`...: a root
prints `_level%d` (only if its level != 0), a child recurses into the parent then appends `/` and
the name; an **unnamed** child gets a fresh name `instance%d` (using +0x04), which is stored back
into +0x08 and registered in the parent's name table (`fn_8012D400(parentTable, name, node)`, the
table is at `fn_80131FF8(parent)+0xC`). The slash form maps an empty result to `"/"`. The dot form
uses `.` and `instance%d` the same way (0x801498B0).

## 4. Property numbers (`_x`, `_width`, ...)

Table of names at 0x802D6E10 (.data), indexed by the standard Flash property number (used by
`GetProperty`/`SetProperty`; referenced from 0x8014BDE8, 0x8014BED0 and 0x80151F08.. in the next slice):

0 `_x`, 1 `_y`, 2 `_xscale`, 3 `_yscale`, 4 `_currentframe`, 5 `_totalframes`, 6 `_alpha`,
7 `_visible`, 8 `_width`, 9 `_height`, 10 `_rotation`, 11 `_target`, 12 `_framesloaded`,
13 `_name`, 14 `_droptarget`, 15 `_url`, 16 `_highquality`, 17 `_focusrect`,
18 `_soundbuftime`, 19 `_quality`, 20 `_xmouse`, 21 `_ymouse`.

`_xmouse`/`_ymouse`, `_width`/`_height` and `_x`/`_y` are in the same Flash pixel space as the
matrix above.

## 5. Clip events

0x801460E8 (`fn_801460E8(clip, name, ?, set)`) turns an event name into a flag in the
clip-event word at **clip+0x10**: `onLoad` 0x1, `onUnload` 0x4, `onPress` 0x400,
`onRelease` 0x800, `onReleaseOutside` 0x1000, `onRollOver` 0x2000, `onRollOut` 0x4000,
`onDragOver` 0x8000, `onDragOut` 0x10000 (name strings at 0x802B75B4-0x802B7614).
0x801465BC dispatches/names the movie-level events (`onEnterFrame`, `onMouseUp/Down/Move`,
`onKeyUp/Down`, `onLoad`, `onUnload`, `onData`; strings 0x802B7638-0x802B7694).

## 6. Other things in the slice

* 0x8014973C-0x80149A90: path functions (above); `fn_80149618` is `clearInterval`: the global
  context pointer `lbl_8037D0F4` (r13-0x62EC) has 64 interval slots of 16 bytes at +0x3A20
  (`{used, callback value, interval float, next-time float}`), count at +0x3E20;
  0x8014947C creates one (`setInterval`).
* `lbl_8037D110` (r13-0x62D0) is the shared "undefined" value returned by native functions.
* Date class: 0x80144FD0-0x801452EC (getters), 0x80145350-0x80145730 (setters), 0x80145900
  registers the methods. `fn_80133510(date)` returns the broken-down time; fields:
  seconds 0x0C, minutes 0x10, hours 0x14, day of month 0x18, month 0x1C, year-1900 0x20,
  weekday 0x24. `getMilliseconds` returns 0 and `setMilliseconds` is ignored.
* 0x80147D08 is the action-bytecode fix-up pass (opcodes 0x81 GotoFrame, 0x83 GetURL,
  0x87 StoreRegister, 0x88 ConstantPool, 0x8B, 0x8C, 0x94, 0x96 Push, 0x99 Jump, 0x9B DefineFunction,
  0x9D If, 0x9F GotoFrame2): it relocates constant-pool indices into value pointers using the
  per-type handler table at 0x802D67B4. The wrappers 0x8014881C/0x80148870 start it.
* 0x80144198: "no slot busy" check over the 64 slots of 0x114 bytes that start the player
  object (`used` 0, `type` 4, `state` 8; type 6 slots are counted down against the count at +0x4500).
* The player object: slots at 0x0000 (64 x 0x114), name table of 0x110-byte entries at 0x4508
  (count at 0x4504), pointer array at 0x4408 with count at 0x4488, count at 0x4500.

## 7. Compiler notes for this unit

* Flags: `-O0`, language C (a `.c` file; as C++ every function gets two extra dead `b` at the end).
* First parameter and some locals are `register` (it lives in r30/r9 instead of on the stack).
* Functions that end `... return; return;` (two trailing returns) are how the original's wrappers
  get their extra `b epilogue`; `return expr; return; return;` for value-returning ones.
* A `for` loop leaves a `nop` after its closing branch; the original uses `while` with the counter.
* Index first (`(depth)[array]`) reproduces `slwi/add idx,base` ordering in the stack push/pop.
* Float compare in an `if` that stores on `<`: `fcmpu; cror eq,gt; bso` is plain `a < b`.
