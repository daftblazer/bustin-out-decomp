# UI library, slice 0x8013C054-0x801440C4 (display list, draw, properties)

Source: `src/ui/Unk8013C054.cpp` (matching ones are marked in the file; this unit is compiled
with `-O0`, `tools/tu_ui.sh`). The library is a **Flash-style movie player**: instances
("characters") form sibling lists, have a 2x3 matrix and a colour transform, are drawn through a
host function table, and are scripted with ActionScript property names (`_x`, `_y`, `_alpha`, ...;
strings at 0x802B7110-0x802B74A4). Nothing in this slice contains 640, 480 or any other screen
size: all positions are in the movie's own units (twips already divided by 20) and the only place
where a screen size can enter is the host side (the graphics-state functions at 0x8014747C-0x80147A70
and the table callbacks below). Everything is `-O0` code: parameters live on the stack, so hook
points are the functions' entry registers (r3 = this, r4.. = args).

## The object (`UiObj`, 0x60 bytes, constructor 0x8012C21C(type, data, parent))

| off | meaning |
|---|---|
| 0x00 | flags word: `type = w & 0x7FFF` (0x8012C7C8), bit 0x8000 = "alternate" flag (0x8012C8A4; most `IsTypeN` tests require it clear) |
| 0x04 | depth (Flash depth; -1 on the list head; script-created instances are > 0x3FFF) |
| 0x08 | name (hash/string id used in the parent's name table, 0x8012D820/0x8012D480) |
| 0x0C-0x23 | **matrix**, 6 floats: a=0x0C, b=0x10, c=0x14, d=0x18, **tx=0x1C, ty=0x20**. Constructor sets identity |
| 0x24-0x43 | **colour transform**, 8 floats: mul A=0x24 R=0x28 G=0x2C B=0x30, add A=0x34 R=0x38 G=0x3C B=0x40 (add terms are /255) |
| 0x44 | pointer to the script property block (below), or NULL when the object was never touched by script |
| 0x48 | parent object (ref-counted, 0x8012C800 = addref) |
| 0x4C | per-character data (`GetClip` 0x8013DD0C returns it; first word = clip depth, -1 = not a clip layer; the same pointer is cast to the type's data class by 0x8013356C, 0x80133598, 0x801335C4, 0x801335F0, 0x80131FCC, 0x80131FF8) |
| 0x50 / 0x54 | previous / next sibling (`fn_8013C054` unlinks) |
| 0x58, 0x5C | zero in the constructor |

Property block at obj+0x44, floats indexed by ActionScript property id (setter 0x80141040, which
rebuilds the matrix and colour transform from it; `props[i] = v` then):

| idx (off) | property | used as |
|---|---|---|
| 0 (0x00) | `_x` | matrix.tx (0x1C) |
| 1 (0x04) | `_y` | matrix.ty (0x20) |
| 2 (0x08) | `_xscale` (percent) | sx = v * 0.01 |
| 3 (0x0C) | `_yscale` (percent) | sy = v * 0.01 |
| 6 (0x18) | `_rotation` (degrees) | angle = v * 0.0174533 |
| 7 (0x1C) | `_alpha` (percent) | colour mul A (0x24) = v * 0.01 |
| 8,9,10 (0x20-0x28) | colour add | add R/G/B (0x38/0x3C/0x40) = v / 255 |
| 11 (0x2C) | `_visible` | **0x8014041C skips the object when this float is < 0.5** |

Matrix rebuild: `a = sx*cos`, `b = sx*sin`, `c = -sy*sin`, `d = sy*cos`, `tx = props[0]`,
`ty = props[1]`. `_width`/`_height` setters go through the bounds routine 0x80140DC4 (min/max
starting from +-1e9, constants at 0x802B73E4/E8) and divide the new value by the measured one.
Property-name dispatch is in 0x80141940 (set member, with the `strcmp`-like 0x8012BFC4) and
0x801420B4 (get member): `_x`, `_y`, `_xscale`, `_yscale`, `_rotation`, `_alpha`, `_visible`,
`_width`, `_height`, `_target`, `_type`, `text`, `textColor`, ...

**Type codes** (`flags & 0x7FFF`), as the draw dispatcher uses them:
0xD and 0x12 (test 0x80132114, `flag` arg 0 = non-alt only): movie clip with a child list at
data+0x1C; 0xE (0x8013209C): clip variant with the child list at data+0x18; 0xF (0x80142CF8):
dynamic text field; 0x10 (0x80142D60): static text records; 0x11 (0x8013DD38, non-alt): two-part
object with a ratio float at data+0x10; 0xC (0x80142C90): plain shape; 0x13 (0x80139D88): skipped by
the list walker. Types 6 and 7 (0x80142C20, 0x80142BB0) are only used by the member get/set code.

## The child list and the draw loop

`UiDisplayList` (4 bytes: `UiHead* head`; ctor 0x8013D148, dtor 0x8013D198, `Clear` 0x8013D5D4)
-> `UiHead` (4 bytes: `UiObj* first`, ctor 0x8013DDA0, allocated through table slot 0) -> a dummy
`UiObj` (type 7, depth -1) whose `next` (0x54) is the first child. Children are plain sibling
links, **not sorted here**; they are inserted in depth order elsewhere (0x8013BCEC and friends).

Draw path (everything below is the recomp hook surface):

1. `UiDisplayList::Draw(this, ctx, flag)` **0x8013D28C**: walks `head->first->next`. For each
   child that is not "alt" and not type 0x13: if its `clip->clipDepth >= 0` it is a **mask layer**:
   it is pushed on a `UiClipStack` (0x8013E558, kept sorted by clipDepth descending, 32 slots,
   count at +0x80) and drawn with `flag = 1` (mask on). Otherwise, first every stacked mask whose
   clipDepth is `< child->depth` is drawn with `flag = -1` (mask off) and popped, then the child is
   drawn with the caller's `flag`. After the loop the remaining masks are closed with `-1`.
   So masks are bracketed by `flag` 1 ... -1 around the draw of the masked siblings.
2. `UiDisplayList::DrawOne(this, ctx, obj, flag)` **0x8013D1F8**: `0x8014747C(ctx)` (push state),
   `0x801475C0(ctx, obj+0x24)` (apply colour transform), `0x80147764(ctx)` (save matrix),
   `0x80147A00(ctx, obj+0x0C)` (apply the object's matrix), **`0x8014041C(obj, ctx, flag)`**,
   `0x801477DC(ctx)`, `0x80147520(ctx)` (pop). `ctx` is the graphics-state object whose first
   float (+0) is an x offset used by the type-0x11 clip path (see below).
3. **`0x8014041C(obj, ctx, flag)`** (0x7A0 bytes) is the type dispatch:
   - returns at once when `obj->0x44 && props[11] (_visible) < 0.5`;
   - type 0xD/0x12 (movie clip): data = obj->0x4C. The first time, data+0x14 is classified by
     looking up the member `_type` (0x8012D6E0, string 0x802B73BC): present -> mode 1 (stored as
     0x10 in the flag nibble), absent -> mode 2. Mode 1 clips are **drawn by the host**: it
     builds a lookup with 0x80149C3C using the member `_target` (0x802B7248), calls through
     `0x802D67B4[type of the result]` and through host slots +0x78 / +0x08. Mode 2 recurses
     into `UiDisplayList::Draw(data+0x1C, ctx, flag)`;
   - type 0xE: `0x801476B4(ctx, &m)` reads the current matrix into a local, records
     `(obj, m)` in the global at `-0x62EC(r13)` via 0x80139B58 (per-frame list of drawn clips,
     the one the 3D-to-2D projection code can read), then `Draw(data+0x18)`;
   - type 0xF (dynamic text field): 0x8013FD90 lays the text out (see below), then if
     `data+0x14` is set it calls host slot +0x44 with it: this is where text is rendered;
   - type 0x10 (static text): data = 0x80133598; for each of `data->0x08->0x30` line records
     (0x38 bytes each at `->0x34`): floats +0x24 = x start, +0x28 = y, +0x2C = font height
     scale, +0x30 = glyph count, +0x34 = glyph array of `{short glyphIndex, short advance}`. Each
     glyph is drawn via 0x8013FAF4(font->0x10[glyphIndex], ctx, flag, &m) with a local matrix
     `m = {size, 0, 0, size, x, y}` at r1+0x20; x advances by `advance * 0.05`
     (twips to pixels, 0x802B73E0). The running start values are initialised to -1e8
     (0x802B73C8) so the first record always resets x;
   - type 0x11 (two-part): data = 0x801335C4. Draws `data->8->8` with `ctx->0 = 1.0 - data->0x10`,
     calls host slot +0x70(ctx), then `data->8->0xC` with `ctx->0 = data->0x10`, +0x70 again,
     restores. (`ctx->0` is a float the host reads.)
   - type 0xC (shape): draws `data(0x801335F0)->8` with 0x8013FAF4.
4. `0x8013FAF4(shape, ctx, flag, matrix)` and `0x8013FBB4` (mask variant, uses 0x80147A70 with the
   shape's bounds `shape+8`): push matrix if given (0x80147764 + 0x80147A00), call host slot
   +0x74 with `(shape->0x18, ctx)` when `shape->type == 1` (type 0xB = nothing), pop. The
   shape's own points are never touched by this library; the host callback does the real draw.
   0x80140BBC is the same walk for the **mask pre-pass** (`DrawUnmasked` 0x8013D4AC calls it
   for non-clip children).

## Host function table (global `lbl_8033D1E0`, 0x7C bytes, 31 slots)

This is the one platform interface; the library calls it as
`lis r9,-0x7FCC; lwz r0,-0x2E20(r9+slot)` then `blrl`. Defaults are installed by the init at
0x8012AD64. Slots seen from this slice (offset = byte offset in the table):

| off | use |
|---|---|
| 0x00 | `void* alloc(unsigned size)`: every `operator new` of the library (`__nw__6UiHeadUi` 0x8013DE30, UiData A-F) |
| 0x04 | called from 0x8012AD10 wrapper, 0x8013E760-adjacent and the text path (`this->data+0x14` argument) |
| 0x08 | `void free(void*, unsigned size)` (`UiHead::Delete` 0x8013E760); also loaded in 0x8013FD90, 0x8014041C |
| 0x0C | 0x8014041C (script-drawn clip) |
| 0x10, 0x50 | 0x8013F62C |
| 0x20, 0x24, 0x28 | 0x801438E4, 0x8014373C, 0x80143E30 |
| 0x3C, 0x40 | 0x8013FD90, 0x80141940 (0x40: called when a text object's field is released) |
| 0x44 | 0x8014041C, **dynamic text field draw** (`data+0x14`) |
| 0x70 | 0x8014041C type 0x11 only: called with `ctx->0` = ratio / 1-ratio around each half |
| 0x74 | **draw shape**: `(shape->0x18, ctx)` from 0x8013FAF4 |
| 0x78 | 0x8014041C (script-drawn clip) |
| 0x10C | 0x80143E30 |

A widescreen hook on the host side only needs slots 0x74 (shapes), 0x44 (bitmaps) and the
graphics-state calls 0x80147A00 (matrix), 0x801475C0 (colour), which every draw goes through.

## Other things in this slice

- **Instance creation** 0x8013C0E0 (0x5B0 bytes, "place object"): looks the instance up by id
  (0x8013BCEC), removes an old one (`Release`), then builds the per-character data by kind:
  5 -> `UiDataC`, 4 -> `UiDataA` (child list at +0x18), 2 -> `UiDataB`, 0xA -> `UiDataE`,
  1 -> `UiDataD`, 8 -> `UiDataF`; wraps it into the right `UiObj` class (types 0xD/0xE/0xF/...).
  0x8013CB40 is the wrapper that applies a placement: `obj->matrix(0xC..0x23)` from arg
  `[0x54]`, `obj->cxform(0x24..0x43)` from arg `[0x50]`, `data->0x18 = [0x58]` and float
  arg `f1` into a 0xE/0x11 data block (+0x10), **only when `obj->0x44 == NULL`**.
- **Timeline commands** 0x8013F62C(this = timeline, list, parent, frame): `timeline->frames`
  (+4) is an array of `{int count; UiAction** items}` (8 bytes per frame); each `UiAction` starts
  with a type word: 1/2 nothing here (1 also handled by 0x8013F7E4/0x8013F8C0: they feed
  `act+4` to 0x8014ADB4(gfx, ...) / 0x801396A4(player, ...)), **3 = PlaceObject**
  (`UiDisplayList::0x8013CD18(list, act+4, parent)`), **4 = RemoveObject**
  (`UiDisplayList::RemoveHandle(act+4)`), 5 = host callback slot +0x10(`act->4`), 6 = host slot +0x50
  with a lookup in the parent's data, 7/8 nothing. `UiTimeline::Lookup` 0x8013F99C maps a label
  name to a frame number (-1 when missing).
- **PlaceObject record** (read by 0x8013CD18, then 0x8013C8CC/0x8013CB40/0x8013C0E0): word 0 =
  flags (bit 0 = move an existing instance, otherwise create), +4 = depth, +8 = character id,
  matrix pointer `rec+0x0C` and colour transform `rec+0x24` are passed only when the matching flag
  bit is set (both are in movie units), +0x2C = ratio float, +0x34/+0x38 = name / clip actions.
  0x8013CB40 copies the matrix into `obj+0x0C` and the cxform into `obj+0x24` only when
  `obj->0x44 == 0`, i.e. an instance whose properties were never set by script keeps the
  timeline's transform; once script sets `_x/_y/...` the property block (obj+0x44) wins and the
  matrix is rebuilt from it by 0x80141040.
- **Bounds** `UiObj::GetBounds(UiRect*)` 0x80140D38 fills `{xmin=1e9, ymin=1e9, xmax=-1e9,
  ymax=-1e9}` and runs the mask pass `UiObj::DrawForBounds(ctx, rect)` 0x80140BBC with the
  collecting context `lbl_8037D124` (`-0x62BC(r13)`); shapes report through 0x80147A70 instead of
  being rendered. `_width`/`_height` come from this, so widescreen-scaled matrices change them.
- **Depth rule** 0x8013D080: a placed instance is released automatically only when depth > 0x3FFF.
- **Pointer sets** `UiObjSet256` (0x8013E24C/E2C4) and `UiObjSet128` (0x8013E370/E3E8): fixed
  open-addressed tables of instances (the 128-slot one lives in the player context `lbl_8037D0F4`
  (`-0x62EC(r13)`) at +0x3814 and is used for event-handler flags, 0x8013FC60).
- **File fixup** 0x8013E7B8 (relocate) / 0x8013EF2C (unrelocate): the loaded movie image stores
  offsets; these add/subtract the load base in the per-character arrays (`{count, ptr}` pairs).
- 0x80142ED8-0x80143FC4: string/text helpers (`80111ECC` = strcmp-like, `80111F74`), not yet read.
- Event flag helper 0x8013FC60: sets/clears one of 200+ event bits (`0x802B743C` table) in
  `obj->0x14 >> 8`.

## Recomp advice from this slice

- Screen-space coordinates are `matrix.tx/ty` (+0x1C/+0x20) and the property block `_x/_y`
  (props[0], props[1]); both are in the movie's pixel units. Anything that composes parent
  matrices happens in the 0x80147xxx graphics-state calls (slice D), not here.
- `ctx->0` (a float) is written by 0x8014041C around the host slot +0x70 calls
  (`1.0f - obj->0x10`), so a hook that wants "x offset" must not clobber it.
- No frame counters or fixed-size assumptions in this slice; the only constants are the 0.05
  twip scale, 0.01 percent scale, 1/255 colour scale, degree-to-radian 0.0174533, bounds sentinels
  +-1e9 and the clip-depth/0x3FFF rules.

## Dynamic text field setup: `0x8013FD90(obj, scope)` (0x68C bytes, read from the disassembly, not matched)

Called from `UiObj::Draw` (type 0xF) every time the field is drawn, before the host's text call. `data` = `fn_8013356C(obj)`
(the text field's per-instance block, `UiClip`-shaped); `res` = `data->8` (the field's definition).

What it does, in order:

1. Works out the **text to show** (`0x110(r1)`, a string pointer) and whether it is "dirty" (`0x114`). Start: dirty if `data->0x10`
   (the previous string object) is null, or if it is set but `data->0x14` (the host text handle) is null.
2. Default text = `0x80111E30(res->0x38, 0x24)` (an `strchr`-style call on the variable-name string at `res+0x38`
   for `'$'`, 0x24) when `res+0x38` begins with a character, else the field's initial text `res+0x34`.
3. If the field is bound to a **variable** (`res+0x38` non-empty): walks `scope` up its parent chain (`+0x48`) until it is a
   movie clip (`0x80132114`), looks the variable up with `0x80149C3C(&lbl_8033D2A8, scope, 0, name, 1, 1)` and
   converts the result to text (`0x80132420`, `0x80131E8C` / `0x8012D9C4` for string objects). Compares with the
   string already shown (`0x80111ECC` = `strcmp`); if different, replaces `data->0x1C` (new string object, built by
   `0x8014FD8C` after allocating 8 bytes with `0x8012C44C`) and marks the field dirty.
4. If dirty: releases the old string objects (`data->0x10` and `data->0x18`, each through the per-type release table
   `0x802D67B4[type]`), makes new ones holding the text, then **recreates the host text object**:
   - frees the old handle `data->0x14` through host slot `+0x40`;
   - finds the font as `obj->0x4C->8->4`'s shape table (`+8`), indexes it by `res->0x18` (the font id) and takes `->8`;
   - calls **host slot `+0x3C`** and stores the result in `data->0x14`:

     `handle = slot3C(font, f1 = res->0x08, f2 = res->0x0C, f3 = res->0x10, f4 = res->0x14, r4 = res->0x1C, r5 = res->0x2C, r6 = data->0x20, f5 = res->0x24, r7 = text)`

   The four floats at `res+0x08..0x14` are the text box's rectangle in the movie's own units (the matrix applied by
   `UiObj::Draw` places it); `res+0x24` is a float (size or scale); `res+0x1C` and `res+0x2C` are integer flags
   (alignment / multiline / selectable are the likely meanings). `data->0x20` is the host-side per-instance value.

For the recomp: the field's box and its font size are in movie units, so they follow the matrix and any scaling the
2D layer applies to draws made from the type-0xF path. Only the text itself is created here; the pixels come from the
host's slot `+0x44` call in `UiObj::Draw`.

## Instance creation: `0x8013C0E0` (0x5B0 bytes) -- what a PlaceObject does to the display list

Source: `fn_8013C0E0` in `src/ui/Unk8013C054.cpp` (control flow follows the original; not byte-matching).
Called from `0x8013C8CC` -> `0x8013CB40`, which `0x8013CD18` reaches for every type-3 timeline command.

```
fn_8013C0E0(list, depth, character, name, parent, force, userdata, &outObj, &outCreated)
```

1. Look up what already sits at `depth` in `list` (`0x8013BCEC`, which also reports where it would be inserted).
2. Decide create or reuse:
   - nothing there: create;
   - `force` set: drop the old instance (`0x8013CF5C`) and create;
   - an old one that is *not* "alt" (`0x8012C8A4` == 0): **reuse it**, `created = 0`;
   - an old "alt" one: if `name` is given and equals its name, keep it as the object but still `created = 1`;
     otherwise create.
3. When creating, the **character definition's type word** (`character->0`) picks the data block and the object type:

   | `character->0` | data class | alloc | object type | Notes |
   |---|---|---|---|---|
   | 5 | `UiDataC` | 0x20 | 0xD (movie clip) | `frame = -1`, flag word `\|= 0xC0`; child list at +0x1C |
   | 4 | `UiDataA` | 0x1C | 0xE | child list at +0x18; flag word cleared |
   | 2 | `UiDataB` | 0x24 | 0xF (dynamic text) | definition pointer at +8, +0x20 copied from the definition |
   | 10 | `UiDataE` | 0x10 | 0x10 (static text) | |
   | 1 | `UiDataD` | 0x10 | 0xC (shape) | |
   | 8 | `UiDataF` | 0x14 | 0x11 (two-part) | |

   Word 1 of every data block is set to the **parent clip's current frame** (`parent->clip->0x10`), or -1 with no parent.
4. A new instance is allocated and linked by `0x8013BF10`. A reused one is re-linked when its depth changed
   (`0x8013C054` unlink, `0x8013BFCC` insert) and gets the new data block.
5. Clips (0xD, 0xE) are also appended to the player's per-frame list at `player+0x1408` (count at `+0x1808`)
   and reference-counted. A dynamic text field (0xF) is set up at once with `0x8013FD90`.
6. A name, when given, becomes a string value (`0x8014FD8C`), is stored in `obj+8` (the old one released through the
   per-type release table `0x802D67B4`) and is added to the parent's name set (`0x8012CEF0`), which is what script
   path lookups like `_root.menu.button` walk.
7. Finally: reference the parent, release the old parent, `obj+0x48 = parent`, `obj->clip->8 = character`,
   `obj->clip->0 = userdata`, and report the object and whether it was created.

For the recomp: **nothing here reads a screen size or a position.** Position and scale arrive later, from the
PlaceObject record's matrix and colour transform (`0x8013CB40`, see above). So a placement bug is in the matrix
from the movie data or in what the 2D layer does with it, not in how objects are created.

## The named pool at `0x8037D0F8` (`UiNamedPool`, 0x6708 bytes), `0x80142ED8`-`0x80143E30`

A reference-counted cache the UI library keeps for named resources (images, fonts). `lbl_8037D0F8` (`-0x62E8(r13)`) points to it.
It holds no positions or sizes; it is listed so nobody looks for them here.

| Offset | Meaning |
|---|---|
| `0x0000` | 64 pool entries of 0x114 bytes: `+0` in-use flag, `+0x100` data pointer, `+0x104` host handle, `+0x108` size, `+0x10C` reference count |
| `0x4500` | number of pool entries in use |
| `0x4504` | number of named entries |
| `0x4508` | named entries, 0x110 bytes each: `+0` name (0x100 chars), `+0x100` key |

Source in `src/ui/Unk8013C054.cpp`: `0x8014351C` find by name (the name is normalised by `0x80142ED8` first), `0x801435F0` find by key,
`0x80143694` add a reference, `0x801436DC` add a reference by name, `0x8014373C` drop a reference (the last one frees the data,
calls host slot `+0x24` with the handle and runs `0x80143400`), `0x801437F8` drop by key, `0x8014384C` exists by name, `0x80143B74`
take a free pool entry, `0x801438A8` give one back, `0x80143DDC` forwards to `0x80143E30` on the global. All match.

### Per-function notes for the named pool (`UiNamedPool`)

None of these reads or writes a position, size or scale; all are bookkeeping for named resources.
"Tries" is the number of compile-and-compare runs it took.

| Function | Tries | What it does | What it needed to match |
|---|---:|---|---|
| `0x8014351C` | 1 | Find a named entry by name; the name goes through `0x80142ED8` into a 0x100-byte local first | nothing |
| `0x801435F0` | 1 | Find a named entry by key | nothing |
| `0x80143694` | 2 | Add a reference (`refs` at `+0x10C`) and return the entry | `++e->refs` (the long form `e->refs = e->refs + 1` is one load short) |
| `0x801436DC` | 3 | Add a reference to the entry with this name | the lookup result in a local, then a plain `return` (a `do { return } while (0)` is one instruction too long) |
| `0x8014373C` | 3 | Drop a reference; the last one frees the data (`0x801375F8`), calls host slot `+0x24`, runs `0x80143400` | `--e->refs`, and the host slot as a named table field rather than a cast index |
| `0x801437F8` | 1 | Drop a reference by key | nothing |
| `0x8014384C` | 1 | Does a named entry exist | nothing |
| `0x801438A8` | 1 | Return a pool entry (clear in-use, decrement `+0x4500`) | nothing |
| `0x80143B74` | 1 | Take a free pool entry (64 of them, 0x114 bytes each) | nothing |
| `0x80143DDC` | 1 | Forward four arguments to `0x80143E30` on the global at `0x8037D0F8` | nothing |

- `0x80143400` (`UiNamedPool::Unk80143400`, 3 tries, match): remove a named entry from the table of 32 at `+0x4508` by moving the last entry
  into its place (`names[i] = names[--nameCount]`). No positions or sizes. Blocker on the way: the source address of the struct copy has to
  be computed after the decrement and the destination before it, so it must be one expression (`names[i] = names[--nameCount]`), not two statements.
